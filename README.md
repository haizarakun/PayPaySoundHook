# PayPay Sound Hook

![version](https://img.shields.io/badge/version-1.00-blue)
![license](https://img.shields.io/badge/license-personal%20use%20only-orange)
![platform](https://img.shields.io/badge/platform-Android%20(root)-lightgrey)

PayPayアプリ（`jp.ne.paypay.android.app`）の決済完了音・チャット音を、自分で選んだ音声ファイルに差し替える LSPosed モジュール。

- パッケージ名: `com.paypaysound.hook`
- バージョン: 1.00

> 本ツールは PayPay 株式会社および PayPay 関連サービスとは一切関係のない、非公式の個人開発ツールです。
> "PayPay" は各権利者の商標です。リバースエンジニアリングによりリソース名を特定し、ローカル端末上でのみ動作します。
> PayPay 本体の APK やサーバー通信内容は一切改変・傍受しません。

## 機能

アプリを開いて音声ファイルを選ぶだけで、再ビルドなしで即座に反映される。

| 対象 | PayPay 側のリソース名 |
|---|---|
| 決済完了音 | `payment_complete_pay2_sound` / `payment_complete_pay2_settings_sound` |
| チャット受信音 | `incoming_message` |
| チャット送信音 | `outgoing_message` |

各項目に「▶ 再生」があり、アプリ内で試聴できる（再生中は「■ 停止」に変わる）。

`incoming_message` / `outgoing_message` は送受金の通知専用ではなく、PayPay のチャットのメッセージ音そのもの。チャットを1通送っただけでも送信音が鳴る。決済完了音だけ差し替えたいときは、種類ごとに ON/OFF を切って元の音に戻せる。

ON/OFF はフラグではなく「差し替えファイルがあるか」で表している。OFF にするとファイルを `<名前>.off` に退避するだけなので、選んだ音源は消えない。

### 対応フォーマット

拡張子ではなくファイルの中身（ヘッダ）から判別する。Android 標準の MediaPlayer / SoundPool が対応している形式なら基本的に使える。

| 形式 | 対応 |
|---|---|
| MP3 | ○ |
| WAV (PCM) | ○ |
| OGG Vorbis | ○ |
| AAC / M4A | ○ |
| FLAC | ○（API 21 以上） |

## 動作要件

- root 化端末（Magisk / KernelSU）
- LSPosed
- **PayPay 自体に Superuser 権限を許可**しておくこと（Magisk アプリの「Superuser」タブ）

### 動作確認済み

| 項目 | バージョン |
|---|---|
| PayPay | 5.69.0 |
| Android | 17 / 15 |
| minSdk | 27（Android 8.1）以上 |

リソース ID ではなく `getResourceEntryName()` による名前一致でフックしているため、PayPay 側の更新で ID 値が変わっても追従できる。ただし**リソース名自体**が変わった場合は追従できない。そのときは診断画面のログに実際のリソース名が出る（`[PayPaySoundHook]` タグ）ので、それを見て直す。

### なぜ PayPay 自体に root 権限が必要か

Android 11 以降のパッケージ可視性制限により、本モジュールの持つデータを PayPay プロセスから通常の方法（ContentProvider / `forceQueryable`）で読み取れない。そこで PayPay 自身のプロセス内で `su` を呼び、本モジュールの内部ストレージにあるファイルを直接読み出している。`su -mm` でマウント名前空間を維持し、SELinux ラベルの問題を避けるため事前に空ファイルを非 root 権限で作ってから root で書き込む、という手順を踏む。

## セットアップ

1. Android Studio でビルド（または `./gradlew assembleRelease`）
2. 署名し直してから APK をインストール（下記「署名」）
3. LSPosed Manager でモジュールを有効化し、スコープに `jp.ne.paypay.android.app` と**本アプリ自身**を追加
4. Magisk アプリの「Superuser」タブで `jp.ne.paypay.android.app` に root 権限を許可
5. アプリを開いて音声ファイルを選択
6. PayPay を完全終了 → 再起動 → 反映を確認

本アプリ自身をスコープに入れないと、画面上の「モジュール有効」判定が働かない。

### 署名

このリポジトリに配布用の署名設定は置いていない。そのままビルドした APK はデバッグ鍵で署名されるため、配布にも上書き更新にも使えない。ビルドした APK を手元で `apksigner` で署名し直すこと。

鍵を変えると、既にインストール済みの端末へ上書き更新できなくなる。同じ鍵を使い続けること。

## 仕組み

`Resources#openRawResourceFd` / `openRawResource` をフックし、`getResourceEntryName()` で名前一致したリソースだけ差し替える。

差し替え用の音声はアプリ自身の内部ストレージ（`/data/user/0/com.paypaysound.hook/files/`）に保存され、PayPay プロセス側からは `su -mm` 経由でこのファイルを直接読み出し、PayPay 自身のキャッシュディレクトリにコピーしてから再生に使う。

## アップデート

起動時に GitHub の最新リリースを見にいき、タグ名が手元の versionName より新しければ、その場でダウンロードして入れ替える。

| ファイル | 役割 |
| --- | --- |
| `update/UpdateInfo.java` | 最新リリースの JSON（タグ名・APK の URL・本文）を読む |
| `update/UpdateChecker.java` | リリース情報の取得と APK のダウンロード |
| `update/ApkInstaller.java` | 署名の照合、su でのインストール、OS 標準インストーラへの受け渡し |
| `update/ForceUpdateGate.java` | 起動時の検知とダイアログ |

### 挙動

新しいリリースが見つかると、閉じられないダイアログが出る。戻るキーも効かない。更新するまでアプリは使えない。

ダウンロードした APK は、インストール済みのものと署名が一致するかを確かめてから進む。一致しなければ破棄して再試行を促す。

署名の照合が通ったら**インストールの直前で一度止まり**、入れ替え方を選ばせる。

| ボタン | 動き |
| --- | --- |
| インストール | root 権限で、Android の確認画面を通さずに入れ替える |
| Android の画面で入れる | OS 標準のインストーラに渡す（確認画面が出る） |
| 終了 | アプリを閉じる |

root が使えない端末では、「インストール」を押しても自動で OS のインストーラに落ちる。

起動時の自動チェックが通信に失敗したときは黙って見送る。電波が無いだけでアプリが使えなくなるのを避けるため。

入れ替えても LSPosed のスコープ設定は残るが、反映には PayPay 側の再起動が必要。

### リリースの作り方

タグ名は versionName と一致させる（versionName が 1.01 ならタグは `v1.01`）。比較は区切りごとの数値で行うので、`1.10` は `1.9` より新しいと判定される。

1. versionCode と versionName を上げてリリースビルド
2. 手元で `apksigner` を使って配布用の鍵で署名し直す（Actions が吐いた APK をそのまま上げないこと）
3. GitHub で新しいリリースを作り、タグを `vX.XX` にする
4. APK を1つ添付する（ファイル名は自由。添付の中から最初の .apk を拾う）
5. リリース本文がそのまま更新内容としてダイアログに出る

アプリが見にいく先は次の固定 URL で、GitHub 側が最新リリースへ解決する。

```
https://api.github.com/repos/haizarakun/PayPaySoundHook/releases/latest
```

リポジトリが Private の間、この URL は認証なしでは 404 になるため、アプリ内の更新は動かない。

## 診断

アプリ内の診断画面に、動作条件と直近のログを1枚にまとめて出す。音が変わらないときはここを上から確認する。

| 項目 | 内容 |
| --- | --- |
| 動作条件 | su が通るか、モジュールが実際にロードされているか、PayPay のバージョン |
| 差し替え音 | 種類ごとの ON/OFF、ファイルの大きさ、ヘッダから判定した形式 |
| 直近のログ | 更新チェックやインストールの経過 |

ログは logcat に加えて、アプリの内部ストレージに直近 500 行だけ残す。端末やアカウントを特定できる情報は入れていない。
